# 未来需求与暂缓事项清单（Backlog）

本文件用于记录当前阶段暂不实施、但后续需要推进的产品与工程需求。

---

## 1. 模型与配置异常处理机制（避免异常直接落入人工兜底）

- **记录时间**：2026-11-28
- **状态**：暂缓（Deferred）
- **现状问题**：
  - 当前当 Tier 1b 决策模型（`/v1/systemone`）出现配置错误、超时或接口异常，或 Tier 2 RAG 上游 LLM 发生超时/调用失败（`llm_synthesis_failed`、`tier2_error_fallback`、`tier2_unavailable_fallback`）时，系统会统一降级并向读者直接回复「人工兜底模板」，同时在馆员工作台创建人工待办工单。
  - 这会将**系统/配置/上游模型故障**与**真实业务无解（需馆员人工核查）**混为一谈：一方面读者明明问的是常规公开问题却收到人工兜底，体验不合理；另一方面上游波动时会向馆员待办队列灌入大量无效工单。
- **后续目标**：
  1. 严格区分「配置缺失/上游模型超时异常」与「检索无证据/需人工业务核查」两类路径。
  2. 为配置异常增加启动期自检与管理员面板健康告警，及时暴露失效的 API Key / Base URL / 模型名。
  3. 为上游短暂超时/波动增加受控重试、备用模型切换或纯检索降级策略；若仍不可用，向读者返回合理的系统繁忙提示而非冒充业务无解，并避免无差别污染馆员待办队列。

## 2. 紧急事件（Emergency）值班主动出站告警

- **记录时间**：2026-11-28
- **状态**：暂缓（待确定外部通知渠道）
- **现状**：读者触发紧急分流时，系统立即回复值班电话并在馆员工作台顶部红色横幅置顶展示，但暂无主动推送值班人员的通道。
- **后续目标**：确定告警渠道（如企业微信群机器人、邮件或短信）后，接入 `emergency` 事件的实时主动推送。

## 3. 未回复 `open` 工单间隔追问的冷却回执

- **记录时间**：2026-11-28
- **状态**：暂缓（Deferred）
- **现状**：读者在已有 `open` 工单时继续发送同主题消息，当前为防短时间连发刷屏采取静默追加；但在间隔较久再次重发，或首次建单处于影子模式从未实发回执的场景下，读者会感觉完全没有回应。
- **后续目标**：引入冷却窗口（如距上次实发回执超过 2 分钟，或该工单从未向读者实发过回执时，补发一句简短的「已在待办队列中」确认语）。
